## 一句话介绍

**PawSure 宠诺**——为宠物打造的、可信赖的**终身健康护照**。

- 中文 Slogan：让每一次托付，都更安心。
- English：Every pet comes with confidence.

繁育者 / 猫舍犬舍 / 宠物店在日常中记录一只宠物的健康历程，临到出售或送养时，
一键生成一份**可信、防篡改的健康护照**；护照随宠物转移给新主人，新主人认领后
可在**同一条终身时间线**上继续记录。AI 全程协助：结构化日志、答疑、生成就诊分诊报告，
并主动盯住异常。

---

## 我们要解决的问题

宠物交易里，"健康"几乎全靠口头承诺：

- **买家**无法核实卖家口中的"打过疫苗、做过驱虫、没有遗传病"，售后纠纷高发。
- **负责任的繁育者 / 商家**做得好却无法被证明，优质供给与劣质供给在买家眼里没有区别，
也就拿不到应有的溢价。
- **宠物主人**接手后，过往健康史断档，去医院只能凭记忆复述，沟通低效。

PawSure 把"健康历程"沉淀成一份**可携带、可验证、能随宠物一辈子的凭证**，
让认真养护的一方被看见，让买家敢信、好的繁育者能卖出溢价。

## 目标用户

1. **主要用户：繁育者 / 猫舍 / 犬舍 / 宠物店。** 他们持续记录，并签发护照——这是产品的"杀手锏"。
2. **第二用户：宠物新主人（消费者）。** 这也是增长飞轮：**每一次售出，就多一个长期用户**。

市场优先级：**大中华区优先**（中国大陆 + 港澳台 + 海外华人），并保留面向全球的能力。
界面与 AI 回复均支持**中 / 英**双语。

## 核心概念：健康护照

护照不是"宠物档案页"，而是一份**像证书一样的可验证凭证**：

- **历史在签发时被冻结**——签发那一刻之前的记录被锁定，无法事后补改 / 倒填日期，买家看到的就是真实历程。
- **可验证商家徽章**——只有通过我们团队人工审核（提交营业执照或等效证明）的商家，护照上才会显示"✓ 已认证商家"。
- **证书编号 + 完整性"印记"**——护照带有唯一证书编号，以及一段由记录内容生成的防篡改"印记"哈希；
只要任何一条被冻结的记录被改动，这段印记就会变化，从而成为篡改信号。
- **健康保障（质保）**——商家可把承诺写进护照：保障类型 + 时长 + 条款 + 可选的交付时体检记录，
在签发时一并冻结。护照上实时显示状态（如"生效中 · 剩余 N 天"/"已于某日到期"）。
它让一句口头承诺变成可追溯的合同，显著降低售后扯皮。

**转移与认领流程**：商家发起转移 → 生成一个公开护照链接 / 二维码 →（若商家允许）买家扫码并一键
"认领并保留"，自动创建一个免费的主人账户，宠物归属转移，时间线继续。一份护照**只能被认领一次**：
一旦新主人认领成功，记录就归属该主人，商家无法对同一只宠物再签发第二份。

## 核心功能

- **健康日志（含 AI 结构化）**：用自然语言随手记一条（"今天有点拉稀、没什么精神"），
保存瞬间完成，AI 在后台把它整理成结构化条目（类型、严重度、摘要、标签），不让你等模型。
- **拍照 / 视频记录 + 视觉分诊**：可以只拍一张照片记录；当照片**配有文字说明**时，
文字为准、照片作为佐证，AI 据此补全。**只拍照、不写字时，AI 不会臆测标签或结论**，
仅作为"照片记录"保存——避免无上下文的视觉判断误导用户。
- **AI 助手 + 就诊分诊报告**：基于这只宠物的全部历史对话答疑；一键生成可带去给兽医的
分诊 / 健康报告，提升与医生的沟通效率。商家和主人都能用。
- **主动健康守护（"守护者"）**：每天自动扫描每只宠物的近期日志、体重趋势与严重度信号，
当出现值得关注的迹象（近期严重记录、体重明显下降、短期内多条中度以上记录聚集）时，
**主动推送一条平和的站内提醒**。检测由规则完成（确定、可靠），AI 只负责把结论"说人话"，
因此不会无中生有；同一情况不会反复打扰你。
- **提醒 / 体重 / 文档**：疫苗、驱虫等到期提醒；体重曲线；疫苗证书等文件归档。
- **全字段校验**：邮箱格式、手机号按地区标准**边输入边自动格式化**、体重 / 日期等合法性，
客户端即时反馈、服务端再次校验，中英文错误提示。

## 增长飞轮

> 繁育者认真养护 →（B1 健康保障让护照与"钱 / 纠纷"挂钩，商家**需要**护照）
> → 每次售出签发护照 → 买家认领 → 成为主人用户
> →（A2 拍照记录降低门槛，主人**持续**填记录，习惯养成）
> → 记录更丰富 → 护照更可信 → 商家价值更高 → 形成正循环。

简言之：**让护照成为商家的刚需，让记录成为主人的习惯。**

## 账户与定价模型

配额在创建宠物时**硬性校验**。

**商家 / 繁育者（可签发护照，需先通过认证）**

- `STARTER`：免费，5 只宠物。
- `SHOP`：¥2000/月，50 只宠物（每多 1 只 +¥30/月），支持多人 / 多设备登录。

**宠物主人（消费者，不可签发护照）**

- **主人账户**（唯一的主人档位）：免费，**含 2 只**；之后**每多 1 只 ¥25/月**，**总数上限 10 只**。
通过认领护照、或主人自行注册创建。（注：通过护照认领接手的宠物**不占**自购配额，以保护"商家→买家"的交接。）

**账户区分（也是一道防滥用设计）**：付费商家账户支持多设备同时登录；主人账户**仅限单设备**——
若在第二台设备登录，会提示"踢掉另一台 / 取消登录"。这让商家更难用便宜的主人账户冒充经营使用。

**支付**：采用统一、与具体渠道解耦的结账层。卡支付、**支付宝**、**微信支付**三个入口当前
通过 Stripe 跨境处理（卡为按月订阅；钱包为按月一次性支付）；未配置真实渠道时，演示模式可即时开通用于试用。

## 信任与合规

- **商家实名审核（KYC）**：商家需上传营业执照或等效证明，经我们团队人工审核通过后才能签发护照；
证明文件以**私有**方式存储，仅审核人员可见。
- **签发即冻结 + 防篡改印记**：见"核心概念"。护照的可信度来自"无法事后篡改"，而非自说自话。
- **数据 / 出海合规思路（已在规划）**：创始人为香港居民，当前采用"以个人 / 个体户身份 + 香港业务登记 + Stripe HK"
的轻量合规路径起步，避免大陆 ICP / 公司前置要求；后续视情况再升级实体。

## 技术概览（高层）

> 给有技术背景的你一个心理模型——不涉及实现细节、密钥或内部结构。

- **前端 / 框架**：Next.js（App Router）+ React + TypeScript，Tailwind 设计系统，统一的品牌组件库。
- **数据**：PostgreSQL（托管），ORM 管理 schema 与迁移。
- **AI**：Google Gemini（经 Vercel AI SDK 接入），支持多模态（读图）；
日志结构化在**后台异步**进行，因此"保存"始终是即时的。AI 具备地区 / 语言感知。
- **存储**：图片 / 文件走对象存储（生产）+ 本地回退（开发）；认证证明走私有存储。
- **认证**：统一账户体系（邮箱+密码 / 手机验证码，签名 Cookie 会话）；按账户类型实施设备数限制。
- **自动化**：每日定时任务驱动"提醒"与"健康守护"，带密钥保护。
- **国际化**：中 / 英词典，类型层面强制两套文案结构一致。
- **部署**：托管平台一键部署，数据库与计算就近部署以保证服务端渲染速度（可达约 0.3 秒含查询）。

**当前已知限制（坦诚告知体验者）**：

- **中国大陆访问**：现阶段在大陆访问主域名**可能需要 VPN**（成因是边缘域名被干扰，
与数据库 / 区域无关）。已规划"香港反向代理 + 自有域名"方案以实现大陆免 VPN 直达。
- 守护者推送文案目前为英文（本地化为后续项）；视频暂存储与展示、尚未做 AI 分析。

## 现状与路线图

**已上线**：终身健康日志 + AI 结构化、拍照记录、AI 助手 + 分诊报告、
主动健康守护、健康护照（转移 / 认领 / 一次性）、健康保障质保、可验证凭证（认证徽章 / 证书号 / 防篡改印记）、
提醒 / 体重 / 文档、商家 KYC 审核、跨境支付入口、双语界面、全字段校验。

**规划中（节选）**：

- 大陆免 VPN 可达的托管（香港反代）。
- 按品种 + 年龄 + 历史**自动生成护理日程**（疫苗 / 驱虫 / 美容）并主动提醒。
- **售前护照**：让商家在成交前就能把已记录的健康史作为销售工具分享（适配微信场景）。
- 护照上的**血统 / 谱系**展示；**整窝批量签发**与轻量声誉层（"已签发 X 份、认领率 Y%"）。
- 公开的护照**校验端点**：买家可独立重算并核对完整性印记。
- 真实支付渠道密钥接入；守护者通知本地化；视频 AI 分析。

## 想听你反馈什么

作为早期体验者，最希望听到你对以下几点的判断：

1. **护照的可信度**：作为买家，这样一份"冻结历史 + 认证商家 + 证书号 + 防篡改印记"的护照，
  能不能真正让你"敢信"？还差什么才足够？
2. **商家的刚需程度**：健康保障 / 质保写进护照，是否足以让一个繁育者愿意为此持续记录、甚至付费？
3. **记录门槛**：拍照即记 + AI 结构化，是否真的把"懒得记"这个最大流失点降下来了？
4. **主动守护**：每天一条"该留意一下"的提醒，是贴心还是打扰？阈值是否合适？
5. **定价**：商家与主人两套档位与配额，是否清晰、是否合理？
6. **技术 / 体验问题**：任何加载、卡顿、文案、双语、校验或异常，尽管反馈。
